# 脚本与交稿检查方法

只有在用户选定创作方向、要求直接写脚本，或提交现有脚本时读取。

## 写脚本

先用几句话确认：选了哪个方向、视频发哪里、预计多长、要展示什么、还缺什么。随后按时间顺序写镜头，每段只保留：目的、画面、口播、屏幕文字和所需素材。

推荐顺序：

1. 开头先给问题或结果。
2. 进入具体场景。
3. 展示产品名称和关键操作。
4. 展示可核验的结果。
5. 自然收尾并给行动引导。

口播量要和实际时长匹配；等待、加载和结果展示要留时间。不能确认的结果写成“待录制或待核实”，不要写成已经发生。

## 检查重点

- 产品名、核心功能、行动引导是否出现。
- 甲方要求的画面、评论区、封面和话题是否遗漏。
- 是否混淆了两个不同能力，或把建议写成保证。
- 是否出现没有来源的数字、排名、效果承诺或版权风险。
- 是否仍然符合用户自己的表达方式。

检查结果只给三类：已覆盖、需要补充、存在风险。不要把完整内部编号表直接塞给用户。

## 审核已有脚本

先给一句结论：可以交、小改、大改或信息不足。然后按影响排序列出最少的修改项：漏了什么、风险在哪里、补哪一句或哪一个镜头。用户没有要求时，不整篇重写。
